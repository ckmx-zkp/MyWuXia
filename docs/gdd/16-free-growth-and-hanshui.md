# 自主成长与汉水药粮：P0 / P1

2026-09-09。本章接续第 15 章，描述本轮实现；旧章节中的版本号和验收数量保留历史意义。

## P0：目标随人，约定有先后

首页可选择学艺、谋生、查案、行侠；学艺再选择散人或武当。偏好以 `p0.intent` 保存，经 `SET_GOAL` 命令更新。存档 v10 接受 v1–v9，缺失偏好的旧档默认查案、散人，不修改身份和历史战斗。

推荐顺序：当前战斗/行动 → 有期限的会面（最早截止优先）→ 已接约定（较早接取优先）→ 当前持续活动 → 伤势恢复 → 所选方向。优先赴约时仍保留玩家偏好，显示余期与当前条件不足。已完成、拒绝、过期的事件不重新催促；三帮结案后不再显示旧的担保/查账催办。推荐直接使用城市导演的当前事件节点与实际相邻路线。

散人可在武馆学拳、刀和罗汉伏魔功，不强制拜入武当。武当目标只在玩家选择这条学艺路后出现。查案和行侠在三帮结案后引向汉水续章。谋生选择当前地点开放的挣钱活动，其他地点可承接行脚。

## P0：正常倍率与资源取舍

旧码头帮工的银两与潜能效率均低于行脚，没有独立价值。本轮仅将其银两从每十五秒六两改为十二两，潜能仍为四点；不调整管理员倍率，不整体放大修炼或剧情收益。

| 差事 | 每分钟银两 | 每分钟潜能 | 实際资格 |
| --- | ---: | ---: | --- |
| 码头帮工 | 48 | 16 | 钱塘码头 |
| 行脚差事 | 40 | 25 | 各地可做 |
| 武当洒扫 | 0 | 18 | 武当弟子；另有六贡献 |
| 汉水联运核货 | 50 | 30 | 联运底账结局 |
| 汉水分段交接 | 32 | 32 | 分段交接结局 |
| 汉水诊棚分药 | 12 | 36 | 民间接济结局 |

这是持续活动收益率，不代表离线推进故事。离线仍只补算活动，保留八小时上限。

## P1：第二章汉水药粮

新增汉水渡口、账房、诊棚，与武当山门相连；诊棚提供实际疗伤和收购草药服务。三条线共享人物和空间，通过不同的前因、成本、交接方式与结局形成差异。

| 三帮前章结局 | 承接原因与准备 | 运输选择 | 可建立的后果 |
| --- | --- | --- | --- |
| 同盟 | 三家账册不一致；学识三点核验，或垫二十两只补缺 | 查实底账可当面对验免战；也可护船、绕行 | 核实账据且整批正渡送达：共同底账联运 |
| 停争 | 各认一程，无可信交接人；请武当见证需入室、教习交情十五、贡献十，也可付二十两请独立船户 | 守住跳板八招或击退拦船人；轻功四百可绕行 | 有交接见证且整批正渡送达：分段约定 |
| 失和 | 帮卡未撤，病户缺药；交三份草药或花三十两购药 | 实际护船或探浅汊绕行 | 民间接济，不改写三帮关系 |

任何路线均可在首次问讯时明确拒绝。护船战败或撤退转诊棚补药：两份草药或十五两，随后绕行送达，只能选择民间接济；也可交还余货退出。基本轻功四百可主动探浅汊，免战但没有正渡整批通行的凭据。垫资不能替代查证，绕行不能冒领正渡护送成功。

最后提交收据才建立持久后果，三个终局互斥并由既有效果凭据防止重复领奖：

- 共同底账：诊棚疗伤六两、荆襄护送危险度十、开放渡口联运核货。
- 分段约定：诊棚疗伤八两、荆襄护送危险度二十、开放渡口分段交接。
- 民间接济：诊棚疗伤九两、开放诊棚分药；护送风险与三帮关系仍由此前局势决定。

诊棚优惠仅在汉水诊棚使用，不替换江南药价；护送改善仅用于荆襄当地。原三帮关系值不被第二章重新写成另一种结局。条件读取 `fate` 为只读世界查询，仍由原命运引擎推进前章。

## P1：武学战术用途

`game/tactics.js` 给出与交手一致的特性，开战写入 `battle.player.traits`，战中不随配置或读档重新计算。旧战斗缺失该字段时所有新增特性视为零，保持原下一回合与随机数。

| 用途 | 门槛 | 实际效果与取舍 |
| --- | --- | --- |
| 护人 | 拳掌与罗汉/纯阳/易筋类护体内功均二重 | 受到强招的伤害乘 0.88，普通进手不享受该减伤 |
| 破甲 | 兵器招式与相合内功均二重 | 强招忽略十八个百分点护甲，护甲最低零；额外消耗内力上限的 5% |
| 续航 | 基础吐纳或全真二重 | 强招基础耗气乘 0.85，破甲额外耗气另计 |
| 撤离 | 基本轻功四百，交手配置轻身游走 | 闪避率增加六个百分点，总上限仍为 30%；汉水另可探路绕行 |

强招耗气 = 内力上限 ×（策略基础耗气比例 × 续航系数 + 破甲额外比例），最终四舍五入。破甲减甲在原护甲上限之后扣除。撤退依旧可直接进行且不发交手收益，不以训练门槛剥夺弱者退路，也不通过撤退凭空回血。

战前配置与修炼页均可展开用途说明。护人和续航使用不同内功；护体、穿甲、节气、绕行并非同一项通用攻击加成。

## 轻后端与真实 LLM

复用现有 `CityHub → /api/narrative/node → MiniMax → mergeOverlay`，汉水作为 `SIDE_EVENTS` 自动进入同一链路。规则、奖励、条件、战斗和结局仍在程序中；原著八树弹窗、三帮命运正文、战报尚未做 LLM 改写。

本轮为模型补入稳定的成长方向、学艺道路、师门身份/阶段、命运节点、主修及重数、人物交情。上下文使用现有 facts 命名空间，进入记忆摘要和缓存键，不新建第二套任务状态。角色仅随世界时钟变化不重新生成。条件对白先按世界事实选好，再送入模板，避免个人文案覆盖回早期对白。

页面区分整理中、已生成、重读缓存、静态回退。请求失败不阻止玩家行动。超时次序为模型请求 60 秒、浏览器 65 秒、nginx 75 秒；解析响应体期间仍保留浏览器超时保护。线上排查确认旧 2200 token 预算可能耗尽在思考过程；提高到 8192 后同一汉水模板实际输出共用 3053 completion tokens，并取得完整正文。只解析最终 content，拒绝 length 截断及仅含 reasoning 的结果；不再把思考文本当成可展示正文。

上线前已对公网旧护药模板进行真实探测：首次 `generated` 约 24.987 秒，重复 `cache` 约 20 毫秒；健康信息显示 MiniMax-M2.5-highspeed、国内官方接口、JSON 存储。当前开发机没有配置密钥，本地 API 明确 `llm=off`，本地浏览器用于验证静态回退；不能据此声称本机已经调用模型。

新增 `node scripts/verify-narrative.mjs <站点地址>`：使用独立测试角色和本版汉水邀请模板，要求首次实际生成且改变场景文字、第二次缓存、选项 ID 不变、规则不被覆盖。它会调用线上模型，不纳入常规离线单元测试。最终上线复验：汉水邀请 generated 35015 ms、cache 26 ms；四个选项及其条件/后继/效果保持。线上浏览器密信卡显示“此番见闻已依你的经历写就”。公网首页及十个 JS/CSS SHA256 与最终 dist 全部一致；发布目录见开发看板。

## 验收与边界

- 184 项自动测试通过，其中 72 条实际 CREATE + reducer + 战斗 + 世界时钟命令路线：四种出身 × 三个随机种子（1/42/20260909）× 散人/武当 × 三种前章结局。家传罗汉拳、臂力分配五点作为本批统一配置；并非所有天赋排列的平衡证明。
- 这些路线不直接植入剧情事实，也不启用管理员倍率；资源通过差事、学习、交手与事件取得。原先基础角色的三条成长路线继续保留。
- 完成第二章并再做一分钟对应差事：散人 1621–1629 模拟秒，剩银 1260–1583、潜能 477–508；武当 2327–2343 模拟秒，剩银 938–1261、潜能 392–423。额外武当时间包括师门学习和考核。这些数值说明可达与资源余量，不是真人游玩计时或长期通胀验收。
- 专项覆盖真实战败/撤退、补药/退出、垫资不产账证、绕行不冒领奖励、结局互斥、实际诊棚扣费/差事开放、重复领奖、v9 迁移、旧战斗确定性续接。战术测试用 64 个同种子对照验证伤害、耗气与闪避确有变化。
- 浏览器使用独立本地新角色验证成长方向刷新保留、行侠路线导航、接受约定后切谋生仍优先兑现、静态回退提示，以及修炼页战术说明。72 条完整路径属于命令级模拟，未声称在浏览器中逐条人工重玩。
- 本版 19 个房间、7 项教学、14 类持续活动、104 个固定事件图。主包仍有大于 500 KB 的构建提醒；完整 NPC 日程、长期势力演化、全地图新门派和全原著 LLM 正文属于 P2。
