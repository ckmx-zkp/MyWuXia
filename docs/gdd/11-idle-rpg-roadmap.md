# 江湖长夜：文字江湖 P0 / P1 / P2 路线图

> 2026-09-07 按最新开发授权重排，覆盖此前以门派、房间数量为阶段门槛的版本。产品方向是文字版群侠游历；P0 固定文案支线，P1 记忆文档与 LLM 增强。

## 一、阶段与依赖

| 阶段 | 目标 | 边界 |
|---|---|---|
| P0 | 核心框架与生活、修炼、战斗、固定支线闭环 | 临安与武当初阶，不接 LLM |
| P1 | 原著剧情双向接入 P0，记忆与 LLM 增强表达 | 程序决定事实、奖励和分支，模型只表达允许的结果 |
| P2 | 同伴、地区、门派、职业、多周目与云存档 | 每项新功能必须接入已有闭环 |

实施依赖：状态与命令 → 条件与效果 → 活动、教学、房间 → 战斗与恢复 → 固定支线 → 验证 → 原著剧情与记忆 → 扩展。

## 二、P0 规则框架

- `src/game/commands.js` 是 UI 角色状态命令入口，处理创角、恢复、旧任务、旅行、设施、战斗和命运。
- `p0-engine.js` 处理房间、活动、学艺、装备、门派考核；`side-events.js` 处理固定支线条件、成本、效果、跳转和经历。
- 旧任务树保留兼容结算；原著剧情全部迁移事件图属于 P1。保留旧顶层字段，增加 `p0` 成长领域，不强行搬迁与改名所有字段。
- 时钟由调用者传入，规则不依赖 React；战斗使用可保存随机种子。UI 不再直接拼接角色状态。
- 新角色武学不随等级自动赠送；旧档已获武学与心得保留，来源记为旧日领悟。
- 武学上限由教学许可和关联基本功共同限制。基本拳脚、兵器、内功、轻功、招架参与成长和战斗。

## 三、P0 样板内容

- 临安 13 房间：城门、御街、客栈、市集、药铺、铁匠铺、武馆、码头、暗巷、府衙、民居、城郊、书肆。
- 荆襄武当 3 房间：山门、练功院、静室。大区旅行复用邻接地图，房间出口同区双向相连。
- 码头帮工产银两与潜能；采药产草药与潜能；洒扫产贡献与潜能；读书产草木学识。
- 静养免费恢复气血与内力；客栈收费即时恢复；药师收费疗伤，避免无钱重伤的死局。
- 六项教学：太祖长拳、六合刀、罗汉伏魔功、武当绵掌、全真心法、华山剑法；最后一项需送药引荐。
- 城南武馆提供散人路径；武当提供入门、初阶学习、一次考核、晋级和绵掌教学上限提升。
- 兵器为徒手、练功木剑、青钢剑，装备影响招式可用性和实战；普通商店不提供神兵。
- 循环：生活资源 → 教学资格 → 基本功与武学修炼 → 装备配招 → 陪练、护送或考核 → 收益与恢复 → 下一目标。

## 四、P0 固定支线契约

五模块保留：情境、对白、抉择、判定回响、传闻。事件、节点、选项均使用稳定 ID。

| 字段 | 作用 |
|---|---|
| room | 校验交互地区与房间 |
| requires / cost | 知识、身份、事实、资源条件和原子消耗 |
| next / failNext | 成功与战败、撤退后的不同后继 |
| combat | 统一自动交手，节点暂停等待结算 |
| effects | 资源、事实与人物状态，只由规则执行 |
| outcome / failText / hearsay | 固定结果文案、失败回响与传闻 |
| terminal | 结局，不再重复发同一奖励 |

样板《一车救命药》：药铺发现 → 直接接车或先备药 → 码头护送战或学识交涉 → 城南交付。战败、撤退进入补药或付费修箱再试。分支可汇合，但保留备药和交涉事实。

交付后，药铺收购草药从三两变五两，武馆开放引荐教学，相关房间固定对白变化。结果必须改变实际玩法。

经历记录保存事件、节点、选择、结果、文本和世界时间；最近 200 条记录与持久事实分开保存。P1 再建立长期记忆摘要与文档版本，有限日志不是完整终身记忆。

## 五、活动与存档

- v6 存档兼容 v1-v5，校验活动、教学资格、装备、房间、事件和待结算战斗。
- 活动保存目标、上次结算时间和毫秒余数；速率是固定内容常量。以后引入动态倍率前，先增加速率版本或冻结快照。
- 一次只能一个活动；开始旅行或战斗时先结算并停止旧活动，不补发交手期间的生活收益。
- 每次离开后最多结算 8 小时。相同时间区间不重复奖励；时间回退不奖励；潜能耗尽或达到上限时停止。
- 离线不推进战斗、旅行与命运期限。回归报告显示时长、收益、截断和停止状态。
- 本地存档支持回溯，不能承诺导入旧档无法回溯获利；可信排行与服务端权威时间属于后续能力。

## 六、P0 验收

1. 从生活获取资源、学艺、修炼、配置到战斗与恢复可走通。
2. 护药的战斗与交涉路线可完成，战败和撤退可补救。
3. 完成支线后实际改变教学和商店收益，刷新保留事实。
4. 武当贡献、教学、修炼、考核和提高上限形成成长路径。
5. 离线重复结算、回退、切换、资源耗尽、上限、存档续战和旧档兼容有确定性测试。
6. 内容检查覆盖房间、教学、后继引用、重复 ID、战斗失败出口、不可达节点和无结局死环；条件组合需流程测试，静态图检查不等于全部可解。
7. 桌面与手机检查创角、房间、修炼、支线和存档交互。
8. 构建 → 部署 → 部署后测试 → 通过后提交、推送。部署脚本的发布前测试保留，线上保留上一版本。

不以强制离线等待或 30–60 分钟时长作为 P0 验收。长期平衡与留存必须实际游玩验证。

### 下一步：取消无交互等待，明确时间用途

- 当前核查：`commands.js` 设置赶路固定 10 秒、旧任务和循环历练配置秒数；`world-engine.js` 每息扣减，到零才触发遭遇、战斗或奖励。这些是行动与收益节奏门槛，不是资源加载进度。区域剧情已在启程前由 `loadZoneQuests` 异步加载。
- 下一步删除赶路、旧一次性任务和进入战斗前没有交互内容的现实倒计时；内容就绪后立即抵达、展示事件或进入交手。真实加载只跟随实际请求显示状态，完成即放行，失败可重试，不设固定最低等待。
- 循环历练不能直接改成无限点击即时领奖：将持续劳动归并生活活动的按时产出，将护送等事件型历练改为实际节点和战斗结算，统一收益入口。
- 修炼、采药、劳动等时间直接对应资源产出或消耗，保留活动计时和离线结算。自动战斗计时承担逐回合推进和战报阅读，另行评估加速或即时结算，不冒充加载。
- 现实等待与世界时间分离：旅行和任务可以即时操作并消耗配置的游戏内时长；迁移前核对命运期限与事件顺序，避免删除等待后意外冻结或跳过世界事件。
- 验收：无资源请求时没有固定加载倒计时；旧存档未完成行动恰好续接一次；奖励不重复、循环收益不可无限点击刷取；旅行遭遇、败退与命运时间均有回归覆盖。
- 此项为待开发计划，本次没有删除运行中的倒计时。

### 内容借鉴与多端方向

- 产品定位为爱好者个人自用，后续覆盖 PC、APP 等终端；优先研究同类作品的文字表达、文案结构、剧情分支、功能及成长闭环。
- 参考《群侠传，启动！》的事件与世界状态连接、金庸群侠传 X 的条件和结果配置、C++复刻版的通用事件指令。整理可复用的内容结构与创作规律，具体引用记录来源及授权边界；个人自用不等同于已获得所有素材的复用授权。
- 保持内容数据、确定性规则、存档与界面平台分离；PC/APP 优先复用同一规则和内容，通过适配层处理存储、音频及生命周期，具体封装技术在多端阶段评估。

## 七、P1：剧情、记忆与 LLM

1. 三帮命运和八棵原著剧情逐棵迁移事件图，统一事实、条件、效果和历史。
2. 增加条件显隐、条件对白、多能力检定、机会窗口与事件调度；P0 不声称这些都已实现。
3. 成长改变剧情解法；剧情改变教学、道路、差事、人物关系与求援。
4. 记忆文档由结构化事实与经历生成，按角色和存档分支隔离，记录来源、版本和过时事实。
5. 后端代理接入 LLM，密钥只在服务端；输入人物设定和允许表达的事实，输出对白、回响和传闻。
6. 固定文案作为回退，断网、超时和错误不阻断游戏。模型不直接发奖励、改伤害或人物生死。
7. 先在一个事件验证一致性、延迟、缓存和费用，再扩大范围。

## 八、P2：扩展顺序

同伴与小队 → 更多区域门派和人物线 → 医毒锻造等生活深度 → 多周目与世界演化 → 按需云存档。

原先四门派、八十房间、三十武学属于扩展参考，不再作为 P0/P1 的功能闭环门槛。排行、赛季与多人不优先于单机体验。
