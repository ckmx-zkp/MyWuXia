# 江湖长夜：放置武侠成长框架与 P0/P1/P2 路线图

> 本文定义从当前剧情原型走向长期放置武侠 RPG 的产品方案、领域框架和分阶段交付标准。参考《放置江湖》的成长闭环，但不复制其内容；《江湖长夜》继续以跨书世界、可改变命运和有声剧情作为核心特色。

## 一、目标体验

玩家每次进入游戏都应明确回答四个问题：

1. 我正在修炼什么，离线期间获得了什么？
2. 下一门武学从哪里学，需要满足什么条件？
3. 当前应该去哪里、找谁、完成什么事？
4. 本次成长如何改变战斗、门派关系与人物命运？

目标闭环：

```text
房间探索 / 客栈传闻
        ↓
发现师傅、秘籍、任务与事件
        ↓
获得潜能、贡献、装备与武学资格
        ↓
在线或离线修炼基本功、武学、内功
        ↓
配置招式、内功、身法与装备
        ↓
自动交手 / 剧情检定 / 门派考核
        ↓
解锁更深地图、上级师傅与命运分支
        ↺
```

## 二、设计原则

### 2.1 等级不再直接赠送武学

等级表示江湖阅历与角色阶段，只负责开放区域难度、师傅考核和系统入口。武学必须通过以下来源获得：

- 拜师传授；
- 任务奖励；
- 秘籍研读；
- NPC 指点；
- 秘境奇遇；
- 门派贡献兑换。

已有存档中已经解锁的武学继续保留，迁移后标记为“旧日领悟”，不能让升级导致玩家丢失能力。

### 2.2 放置必须是可选择的修炼

挂机不再同时平均增加所有收益。玩家一次只能选择一个主要活动：练武、修内功、打坐、读书或门派差事。不同活动产出不同，离线回来显示完整结算报告。

### 2.3 内容入口来自世界

任务、师傅和秘籍优先通过房间、NPC、传闻与事件出现。列表用于整理已经发现的内容，不替代探索。

### 2.4 命运系统承接成长结果

高等级和高武学不只增加战斗数字，还应开放救人、止战、揭密、收徒或改变阵营的选择。失败保留后果和补救路线。

### 2.5 先完成一条纵向切片

每个新系统先在“临安起始章节 + 武当门派”形成完整闭环，再复制到其他区域。不得先铺大量空白门派和地图。

## 三、领域框架

### 3.1 状态分区

未来 GameState 按领域分组，存档仍由统一迁移器管理：

```js
{
  version: 6,
  character: { levelExp, potential, attributes, hp, mp },
  progression: { basics, skills, knowledge, trainingCaps },
  activity: { type, targetId, startedAt, settledAt, rateSnapshot, capSeconds },
  sect: { id, rank, masterId, contribution, reputation, joinedAt, history },
  position: { zoneId, chapterId, roomId },
  inventory: { items, equipment, materials, money },
  quests: { states, choices, rewards },
  world: { time, flags, npcStates, factionRelations, fateEvents },
  meta: { achievements, heritage, settings }
}
```

第一阶段不要求一次完成结构搬迁。新增系统先通过领域命令修改状态，旧字段由 selector 和迁移层兼容，随后逐模块迁移。

### 3.2 统一命令入口

UI 不直接拼接复杂状态。玩法行为转换为命令，由纯函数验证和结算：

```text
START_ACTIVITY        开始练武、打坐、读书或差事
SETTLE_ACTIVITY       在线心跳、退出快照或离线归来结算
MOVE_ROOM             校验出口、时间、体力和遭遇
TALK_NPC              推进师承、任务或命运节点
LEARN_SKILL           校验来源、师傅、潜能和前置
EQUIP_LOADOUT         校验兵器、武学和内功兼容性
START_COMBAT          冻结战斗配置与奖励倍率
SETTLE_COMBAT         一次性结算伤势、内力、奖励和后果
JOIN_SECT             校验入门条件并写入师承历史
ADVANCE_FATE          按世界时间与条件推进事件
```

每条命令返回新状态、领域事件和用户可见日志。随机结算必须使用可保存的随机种子。

### 3.3 离线活动模型

活动保存开始时间、上次结算时间、速率快照和最长结算时长。结算公式：

```text
有效秒数 = clamp(当前时间 - 上次结算时间, 0, 离线上限)
产出 = floor(有效秒数 × 开始活动时冻结的速率)
```

约束：

- 默认离线上限 8 小时，后续通过客栈、家园或传承提高到 12 小时；
- 切换武学前先结算旧活动，不能把过去时间重新计价；
- 系统时间回退时不发奖励，并记录异常；
- 同一时间段只能结算一次；
- 战斗、赶路和剧情倒计时不自动按离线时间完成；
- 回归页面必须出现修炼时长、资源、武学进度和突破结果报告。

### 3.4 成长模型

角色成长分为四层：

| 层级 | 内容 | 主要来源 | 作用 |
|---|---|---|---|
| 阅历 | 总历练、角色等级 | 任务、战斗、探索 | 开放区域和考核 |
| 潜能 | 可消费修炼资源 | 任务、门派差事、传闻 | 提升基本功和武学 |
| 基本功 | 拳脚、兵器、内功、轻功、招架 | 师傅与长期练习 | 决定对应武学上限 |
| 专门武学 | 招式、内功、身法 | 师承、秘籍、奇遇 | 决定实际战斗和剧情能力 |

专门武学等级不得超过关联基本功和师傅许可上限。1–10 重继续作为玩家可读的阶段显示，内部经验允许更细粒度增长。

### 3.5 武学定义

每门武学采用数据定义：

```js
{
  id, name, category, weaponType, faction,
  sources, prerequisites, potentialCost,
  levelCap, masteryStages, compatibility,
  moves, passives, storyChecks
}
```

武学组合由主攻、招架、内功、身法和兵器组成。相合关系提供具体效果，不使用单一“能力值”覆盖全部判定。

### 3.6 门派与师承

门派状态包括身份、辈分、师傅、贡献、门派声望、戒律和历史。首个完整样板采用武当：

- 入门：客栈传闻 → 武当山门 → 道童问答 → 外门考核；
- 三层师承：外门教习、二代弟子、掌门级人物；
- 六类教学：基本拳脚、基本内功、基本轻功、绵掌、剑法、纯阳心法；
- 十二条可重复门派差事；
- 三次晋级考核；
- 一条守规路线、一条离门路线和一条补救路线；
- 贡献只用于门派学习和物资，不直接兑换银两。

### 3.7 房间地图

地图采用“区域 → 章节 → 房间”三级结构：

```js
{
  id, name, scene, exits,
  npcs, facilities, encounters,
  inspectActions, requirements, music
}
```

P0 的临安样板至少包含城门、御街、客栈、药铺、武馆、码头、暗巷、衙门、民居、城郊等 12 个房间。任务列表只显示已经发现的线索。

### 3.8 战斗与装备

保留当前自动交手，每场由配置和角色状态决定结果。扩展点：

- 武器类型限制招式；
- 招式拥有内力消耗、冷却、命中、破招和状态效果；
- 内功提供回气、护体和特殊被动；
- 身法影响先手、闪避和脱离；
- 战后保留伤势、内力、装备耐久与掉落；
- 剧情战斗与普通切磋共用战斗核心，但奖励和死亡规则由上下文决定。

### 3.9 内容与数据校验

新增内容拆分为 skills、sects、chapters、rooms、npcs、items、activities 和 fates。构建时校验：

- ID 唯一；
- 引用目标存在；
- 房间出口双向关系合理；
- 武学前置无循环；
- 师傅能够教授声明的武学；
- 装备类型与招式一致；
- 任务和命运条件可到达；
- 资源文件存在；
- 奖励不会突破数值上限。

## 四、界面框架

主导航调整为：

| 页面 | 主要内容 |
|---|---|
| 江湖 | 当前房间、出口、NPC、设施与可见事件 |
| 修炼 | 当前活动、离线报告、基本功、武学进度与突破条件 |
| 武学 | 武学详情、来源、前置、招式与搭配 |
| 门派 | 身份、师傅、贡献、门规、考核与差事 |
| 行囊 | 装备、药品、材料、秘籍与任务物品 |
| 游历 | 区域/章节地图及已发现地点 |
| 命运 | 事件时间线、人物阶段、势力关系和未决后果 |

回归游戏时优先打开离线报告；报告关闭后回到当前房间。所有成长条必须同时显示当前值、目标值和获得来源。

## 五、P0：形成可持续成长闭环

目标：玩家能够探索、获得武学资格、选择修炼、离线成长并用成长结果完成战斗或考核。

### 交付范围

1. 活动与离线结算引擎：练武、修内功、打坐、读书四类活动，8 小时上限和回归报告。
2. 潜能与基本功：拳脚、兵器、内功、轻功、招架；任务和门派差事产出潜能。
3. 武学来源迁移：停止新武学按等级自动赠送；旧档已解锁武学保留。
4. 武当门派纵向切片：入门、三层师承、六类武学、十二项差事、三次考核。
5. 临安 12 房间探索样板：NPC、出口、观察、设施和任务发现。
6. 当前战斗接入基本功、武学上限和持久气血/内力。
7. 存档升级与迁移，覆盖离线重复结算、时间回退和活动切换测试。
8. 将新增动作接入领域命令；不要求一次重写所有旧剧情动作。

### P0 验收

- 离线 2 小时只结算一次，刷新和导入存档不能重复领取；
- 切换修炼目标前自动结算旧目标，历史时间不能重新计价；
- 玩家必须通过师傅或秘籍获得新武学；
- 完成武当入门到第一次晋级至少形成 30–60 分钟在线内容和一次离线等待；
- 临安任务能够由房间/NPC发现并返回现有剧情树；
- 升级、练功、配招和战斗之间存在可观察的数值变化；
- v1–v5 存档能够迁移且现有进度不丢失；
- 全部规则有确定性测试，生产构建和内容校验通过。

## 六、P1：扩展探索、战斗与经济深度

目标：把 P0 的纵向切片扩展成可持续数周的江湖生活。

### 交付范围

1. 江南六城与大理房间地图，包含城镇、门派和野外三类章节。
2. 少林、华山、峨眉三个完整门派，并支持无门派路线、叛师记录和转投条件。
3. 装备系统：武器、防具、品质、耐久、修理、掉落和材料。
4. 战斗扩展：主动绝招配置、状态效果、兵器限制、破招与战后掉落。
5. 设施经济：镖局、铁匠铺、杂货铺、衙门、市场、寺庙和赌场。
6. 循环任务地域化，替换当前 39 个通用模板，建立护镖、采药、缉盗、探索等任务池。
7. 动态命运扩展到至少 5 条互相关联事件链，驱动 NPC 迁移、阵营和地图状态。
8. 日志、传闻、信件与地图线索统一到“已发现内容”模型。

### P1 验收

- 至少 80 个可探索房间、4 个完整门派、30 门有来源的武学；
- 至少 3 种可行战斗流派，不存在唯一最优搭配；
- 银两、潜能、贡献、材料均有稳定产出和消耗；
- 同一事件至少有成功、软失败和延迟补救三种长期结果；
- 玩家不接原著剧情也能通过生活、门派和探索持续成长。

## 七、P2：长期传承、世界演化与在线能力

目标：形成数月级长期目标，并支持可靠的跨设备运营。

### 交付范围

1. 传承系统：角色达到条件后保留部分武学知识、收藏、称号和家族资源，开启新周目。
2. 世界演化：战争、门派兴衰、NPC 生死与区域控制按事件网络持续变化。
3. 家园与收藏：藏书、兵器谱、弟子、客卿和离线时长扩展。
4. 高阶内容：秘境、宗师挑战、跨区域大型事件和稀有武学路线。
5. 账号、云存档、服务端时间和存档校验。
6. 真实排行、赛季目标和活动配置；管理员工具与玩家客户端分离。
7. 运营数据：新手漏斗、离线回归、门派选择、战斗失败和内容完成率。

### P2 验收

- 传承后存在明确的新路线与成长加速，但不能直接复制全部战力；
- 世界事件能改变房间、NPC、任务和势力界面，而不只改变一段文本；
- 跨设备存档冲突可检测和恢复；
- 排行数据由服务端计算，客户端修改本地状态不能进入正式排行；
- 内容配置可以灰度发布并快速回滚。

## 八、依赖与实施顺序

```text
状态迁移与命令入口
  ├─ 离线活动 → 潜能/基本功 → 武学来源
  ├─ 房间地图 → NPC/师承 → 门派考核
  ├─ 武学定义 → 装备 → 战斗扩展
  └─ 世界事件 → 多区域命运 → 传承与在线服务
```

P0 内部顺序：状态与时钟 → 离线活动 → 潜能/基本功 → 武学来源 → 临安房间 → 武当师承 → 战斗接入 → UI 与内容校验。

P1 必须复用 P0 数据结构，不为每个城市或门派单独写结算逻辑。P2 的服务端能力在单机规则稳定后接入，服务端复用同一套确定性领域规则。

## 九、暂不进入 P0 的内容

- 多人 PvP、帮派战和实时社交；
- 大规模随机装备词缀；
- 付费系统；
- 全部 13 区同时房间化；
- 一次性完成所有门派；
- 为追求功能数量复制大量同质任务。

这些内容会分散核心闭环验证。P0 的判断标准是玩家是否愿意为了下一门武学和下一次考核再次回来。
